# HOMELESS V3.0 — ONE CROSS-SKILL CONTRACT

This addendum has **precedence over legacy SKILL.md on conflicts**; otherwise preserve all previous rich genre/taste/reference rules. The suite is five specialist skills, not five steps that must all be invoked every time. Individual partial requests stop at their requested output.

## Shared invariants
| Constraint | Authoritative V3 value |
|---|---|
| Audience/voice | U.S. viewers 40+, natural American English, dignified human emotion |
| Genre | Homeless/displaced woman + unusual/abandoned property + historical/family mystery + earned restoration |
| Title | <=100 code points; require title-rewrite >=98 if rewriting; no changes after lock |
| Outline | 7 PART, editorial >=98 + hard canon gates |
| Prose | 70,000–80,000 characters body inclusive; preferred 74–78k |
| Counting | UTF-8 strict; Python len(text), including spaces and punctuation and LF; remove only seven `[PART N]` heading lines with their LF |
| Segments | A=PART 1–2, B=PART 3–5, C=PART 6–7, three verified persisted calls |
| QA | Independent auditor + evidenced frozen checkpoints, score >=98, all hard gates PASS, zero defects for READY |
| Repair | Only frozen tickets and declared adjacent dependencies; exact authored replacement; changed SHA always means new QA |
| SEO | Same locked title, grounded plot facts and physical scenes, 170–280-word description, tags <=500 chars, OMNI 10/20/30 seconds |
| Disallowed | Channel Audit, market intelligence/vidIQ dependencies, invented reviews, invented availability, invented output files |

## Contract of authority
1. Current explicit user requirements override defaults unless technically impossible. The title remains locked once approved; if the user **explicitly** changes it, start a new project lineage rather than mutating prior artifacts.
2. `TITLE_CARD.json` has title authority, `STORY_BLUEPRINT.json` has story canon authority, full manuscript has exact delivered prose authority; the frozen QA report has audit authority **only for its source SHA**.
3. A machine PASS proves only JSON/length/hash/format consistency. It never proves originality, character motivation, platform performance, or editorial excellence.
4. Do not silently re-plan approved plot beats mid-script. For a genuine conflict, create a new outline/script version with provenance; re-audit afterwards.
5. If no local history, anti-dup result = UNKNOWN. A partial corpus can't establish global novelty.
6. The user can explicitly request a single skill outside the full pipeline. In standalone mode, disclose which downstream locks were not checked. Do not invent a Project State.

## Cross-skill evidence
`TITLE_CARD.json` title, promise, score, comprehension, serviceability → `STORY_BLUEPRINT.json` 7 parts, clues, reveals, early positions, canon, projected budgets → `CONTINUITY_HANDOFF_A/B/C.json` facts/open loops/closed loops/quotes → segment MANIFEST and final `file_sha256`/`body_sha256` → QA checkpoint/frozen package → versioned repair diff → SEO pack with exact script evidence quotes. Every edge must validate source lineage.

## QA workflow in case of defects
The Auditor identifies problem + location + affected state + desired repair without changing text in REVIEW ONLY. Writer patches exact approved occurrence, preserving immutables. A new QA checkpoint is mandatory after any revision. The V3 tool supports strict surgical replacements only; extensive re-planning requires an explicitly new lineage/re-baseline, not a bypass of diff validation. Repair is not hard-limited to an arbitrary 2 iterations in the source system: favor smallest bounded rounds, report what remains, and stop on uncertain editing permissions.

## Risk and professional realism
No illegal access, forged documents, miraculous authorities, instant title transfer, impossible maintenance procedures or hidden inheritance explained by a single unverified paper. Historical claims inside fiction should be credible and internally consistent. Document/ownership/authority steps need roles, permissions, process and time costs.
